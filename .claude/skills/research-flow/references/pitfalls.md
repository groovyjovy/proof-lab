# これまでにはまったところ

## Lean の証明

- `simp [State.doubtful?]` のように定義を渡すと、simp は先に展開してしまい、`searchTo` の結果についての補題が当たらなくなる。先に `simp_searchTo`(`AppProofs.lean` のマクロ)で直してから展開する
- `first | (A) | (B)` は、A がゴールを残したまま終わっても成功扱いになる。各候補の最後に `<;> done` を付ける
- 状態に Bool の旗を足すと、`simp ... at h` のあとに `if` が残る。`(try split at h)` を挟む
- `{ s with screen }` などの構造体は、`obtain ⟨me, tiles, screen, map, search⟩ := s` で分けてから simp に渡すと、射影が簡約される
- 使っていない束縛は警告になり、警告はエラーなのでビルドが落ちる(`_` にする)

## モデル3

- 範囲を1つの世界にまとめると、状態が掛け算で増えてメモリ(4GB)が尽きる。範囲を分ける
- 届く順番が決まっていないもの(応答、知らせ)は、並べ替えてから状態に入れる
- ログアウトの失敗のたびに検索し直すなど、操作を繰り返すと値が増え続ける遷移があると、状態が尽きない。上限を置く
- 性質は1回の探索でまとめて見る(性質ごとに探索すると、大きい範囲では遅い)

## 突き合わせ

- Python の文字列置換で TypeScript を書き換えるときは、prettier のタブと改行に合わせる(合わないと置換が黙って当たらない)。置換のあとに `assert` で当たったかを確かめる
- 生成器が新しい場面に届くかは、決まった種での `reached` で確かめる

## E2E(Playwright)

- `page.route` の `times: 1` は使わない。使い終わった経路を外すときに、別の経路で止めていた要求まで流れることがあった。止めた回数は自分で数え、返したあとで外す
- サーバーに答えさせてから応答を止めるには `route.fetch()` してから、あとで `route.fulfill({ response })`
- 変更の流れ(SSE)が開いている間は、通信が止まる(`networkidle`)ことはない。待つなら、画面の要素(一覧の `data-search` など)を待つ

## 画面と地図

- 地図の `load` は、背景地図のタイルを読み終えるまで来ない。地図ができた時点の処理は、地図の子の部品(`getMapContext`)で行う
- 関数バインディングの getter は値の変化を知らせないので、地図ライブラリの子が描かれなくなった
- 画面が読むための属性(`data-*`)は、UI の探索や E2E のためのもの。画面の振る舞いは読まない

## UI の探索(Bombadil)

- 画面の外(座標が負)のボタンを押させると、Bombadil が止まる。押せるボタンを画面の中に絞る
- 操作の重みが偏ると、特定のロールや場面に届かない。届かなかった場面は報告に出る
- 本物の画面の探索は再現できない(地図の描画が毎回違う、保存のキーが毎回新しい)。見つけたら記録から読んで E2E にする
