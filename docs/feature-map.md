# 機能マップ

最終更新: 2026-11-21

ユーザーから見た機能の一覧。人間とエージェントの共通語彙にする。
ロールは goal.md 3.1、出口は 3.3、性質は 4章を参照。

## 機能

| 機能 | 使えるロール | 通る出口・入口 | 関わる性質 |
|---|---|---|---|
| ログインする / ログアウトする(保存中はログアウトできない) | 全員 | Better Auth | P3, L1 |
| 地図で地物を見る | 全員 | ベクタータイル | P1, P2, P5, P7 |
| 地物をクリックして属性を見る | 全員(閲覧者には `owner_name` を出さない) | ベクタータイルの属性 | P2, P5 |
| 地物の一覧を見る | 全員 | 地物一覧API | P1, P2, P5, P7 |
| 範囲を指定して地物を探す | 全員 | 範囲検索API(bbox) | P1, P2, P5, P7 |
| 地図に見えている範囲の地物の一覧を見る(地図や権限が変わるたびに読み直す) | 全員 | 範囲検索API(bbox) | P1, P7, P11, P13, P15 |
| ほかの人の保存を、その場で知る(地図と一覧を読み直す。編集中の地物なら警告して読み直せるようにする。結果不明の更新が効いていたと分かれば成功にする) | 全員 | 変更の流れ(`/api/events`) | P1, P7, P11, P14 |
| ポリゴンを描く(描画開始・点の追加・取消) | 管理者、市職員 | なし(画面の中だけ) | P6 |
| 描いた地物を保存する | 管理者、市職員(自分の市だけ) | 保存API | P3, P6, P8, P10, L1 |
| 保存の結果が分からないとき、再送する・やめる | 管理者、市職員 | 保存API | P10, L1 |
| 既存の地物の名前・備考を編集して保存する(地物を選んで「編集を始める」) | 管理者、市職員(自分の市だけ) | 1件を読む API、保存API(更新) | P3, P4, P8, P11, P12, L1 |
| クリックした地物の断片と同じ版で編集を始める | 管理者、市職員(自分の市だけ) | ベクタータイル、1件を読む API | P16 |
| 両側の区画をクリックして、共有境界の位置を一括で確定する | 管理者、両側を編集できる市職員 | ベクタータイル、1件を読む API、保存API(更新) | P16, P17 |
| ほかの人が先に保存していたとき、読み直してから編集し直す | 管理者、市職員 | 1件を読む API | P4 |
| 更新の結果が分からないとき、再送する・やめる | 管理者、市職員 | 保存API(更新) | P12, L1 |
| 職員の編集権限を剥奪する・ロールを変える | 管理者 | Better Auth の admin プラグイン | P3, P9, P15 |
| ログイン中に自分の権限が変わったことを受け取る | 本人 | 変更の流れ(`/api/events`) | P11, P15 |
| ほかの画面で別の利用者としてログインし直されたら、この画面を止めてログイン画面に戻す | 全員 | すべての出口(要求に本人を書く) | P11 |

市職員は、A市職員(a-staff)とB市職員(b-staff)のこと。

## 性質の抜けを見つけた記録

最初の版の表(P1〜P6 だけ)では、goal.md 3.1 の権限のうち三つを、どの性質も確かめていなかった。
2026-11-19 に P7〜P9 として goal.md 4章に足した。

| 権限(3.1) | 抜けていた理由 | 足した性質 |
|---|---|---|
| 閲覧者は公開地物だけ見られる | P1 は市職員の地域分離、P2 は `owner_name` だけを見ていた | P7 公開範囲 |
| 市職員は自分の市の地物だけ編集できる | P1 は受け取る側(読み出し)だけだった | P8 書き込みの地域分離 |
| ロール変更は管理者だけ | どの性質にもなかった | P9 権限変更は管理者だけ |

機能や権限を足したときは、この表で「関わる性質」が空の行がないかを見る。

## テストとの対応

P1〜P4・P6〜P8・P10〜P17 の Lean の証明は `docs/proofs.md` にある。サーバーの性質のテストは `tests/properties/` にある。画面の振る舞いは `src/lib/app/machine.ts` の状態機械にあり、`model/` のモデル3が各範囲の全状態を検査する。本物の画面は `tests/ui/`(Bombadil)が、障害を起こすプロキシ越しにランダムに操作して確かめる。決まった手順を本物のブラウザで流す E2E は `tests/e2e/` にある(P3・P4・P11・P13〜P17)。
画面を動かしてスクリーンショットを撮る `pnpm drive` のシナリオは、この表の行に合わせてある(`docs/screens.md`)。出口は `tests/properties/harness.ts` の `exits` に並べる。
出口を足したら `exits` にも足す。P1・P2・P5 のテストは `exits` の全部に対して回る。
